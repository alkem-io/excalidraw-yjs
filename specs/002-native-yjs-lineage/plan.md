# Implementation Plan: Native-Yjs Lineage Preservation

**Spec**: [spec.md](./spec.md) · **Created**: 2026-06-26 · **Status**: Plan (widened 2026-08-19 for the R2 write-path class)

## Summary

The four review defects are one root cause: the scene is flattened to records and re-encoded through a **throwaway `Y.Doc`** (`buildSnapshotDoc` → fresh random `clientID`) on the wire, in persistence, and on cold-load — collapsing per-property CRDT merge to whole-element LWW. **Proven** (yjs 13.6.31, `/tmp/lineage-probe.cjs`): throwaway re-encode = per-property merge **0/2000**; live-doc-state encode = **2000/2000, zero loss**.

**Widened 2026-08-19 — a second root cause.** The above is the _boundary_ cause. A max-effort re-review found per-property merge is also destroyed **inside the editor**, before any boundary: `Scene.mutateElement` → `writeChangedKeys(ymap, element)` iterates `Object.keys(element)`, so a write through a stale reference rewrites keys a peer just changed, with lineage intact. Fixing every boundary leaves this untouched. Worse, the three defects it produces (write clobber, history desync, version regression) are exactly what the 34 disabled `multiplayer undo/redo` tests covered — the tests FR-008 re-enables as the Phase-1 gate. So the write path must be fixed **first**, or Phase 1 goes RED for reasons this plan never names.

**Key leverage:** the `Scene` ALREADY has the correct lineage-preserving primitives — `encodeStateAsUpdate()` (Scene.ts:1049, live-doc `Y.encodeStateAsUpdate(this.doc)`), `encodeStateVector()` (1062), `encodeSnapshot()` (1203), `applyRemoteUpdate()` (1035, v1+v2 into `this.doc`), and **doc adoption via `new Scene({ doc })`** (425). The PR's wire/persistence/cold-load paths _bypass_ them through the throwaway detour. So the redesign is mostly **delete the detour + route through the native primitives**, not net-new machinery. The in-doc GC (D3/D4) and the editor-Store reseed (FR-005) are the only genuinely new code.

## Invariant suite (the deterministic gate)

Authored RED against the original HEAD first (proving non-vacuity + reproducing the defects), driven green. **Status below is CURRENT, not the authoring-time snapshot** — "RED on HEAD" is retained only where the invariant is still unmet:

- **INV-CONVERGE / INV-NO-RESURRECT** — N-replica property test: random op-sequences (edit-prop, delete, re-add, concurrent) across N in-process Scenes interleaved with INIT/resync; assert semantic convergence on canonical content fingerprints (NOT Yjs byte equality — replicas legitimately differ in byte layout), zero lost edits, zero resurrected deletions. **GREEN (T001 + T032)** — the Scene gate is sharp (all seeds fail if the encoder rebuilds through a throwaway `clientID`) and the app producer no longer rebuilds. The headline gate.
- **INV-PERSIST-MERGE** — concurrent `save(A)∥save(B)` over shared lineage ⇒ stored == per-property merge; order-independent, idempotent. **GREEN (T021/T003).**
- **INV-COLD-LOAD-LINEAGE** — a cold-loaded replica per-property-merges with an INIT-seeded one. **GREEN (T004).**
- **INV-REVEAL** — reappear-after-structural-removal is re-detected by the Store. **GREEN (T005)**; its "ties at `V+1`" premise was FALSIFIED — the Store gates on `prev.version < next.version` and the reseed is not tied.
- **INV-BOUNDED** — over-timeout tombstone + orphan asset REFERENCE reclaimed; store size non-monotone under churn; a deleted image's reference is not sent to a joiner. Bytes are never in the document, so the sweep reclaims references, never storage.
- **INV-SAVE-SKIP** — `isSaved ⇔ nothing changed since the last successful save`; no perpetual redundant save, no false-skip. **GREEN (T007 RED → T026).** The measured defect was worse than predicted: the cache compared live sums against `restoreElements`-renormalised ones, so EVERY save was redundant.
- **INV-WRITE-INTENT** — a write through a deliberately stale reference touches only the declared keys; a peer's concurrent edit to another property survives. **GREEN (T008)** — was RED by whole-object flush. **The new headline gate, below INV-CONVERGE.**
- **INV-HISTORY-LOCKSTEP / INV-VERSION-MONOTONIC** — **the depth-equality wording is FALSIFIED and must not be restored**: an appState-only step makes a `History` entry with no `UndoManager` item, so equal depths cannot hold for a correct editor. Restated behaviourally (a remote apply contributes nothing to local history) and **GREEN (T017)**. `meta.version` monotonicity is **still open — T014b**.
- **INV-ORIGIN** — table-driven over {origin} × {write path}; adding an origin without a declared policy fails. The closed set is `LOCAL` (tracked, published), `STRUCTURAL` (untracked, published — carries the born-tombstone prelude and non-recording writes) and `REMOTE` (applied, never echoed). There is no "local-only" origin: a write to the shared doc cannot be withheld from peers, because the next full-state encode carries it regardless.
- **INV-NO-BINARY-WIRE** — no broadcast frame ever carries file content. **GREEN (T023)**, by construction for protocol-compliant writers: locators are validated on every encode, including deltas.
- **INV-WIRE-ROBUST** — **RESTATED and still open (T027).** "Rejected without desynchronising" is NOT achievable by catching: Yjs apply is not atomic on a decode failure (measured — 10 of 1056 truncation offsets both threw AND mutated). It needs generation replacement, not a `try/catch`.
- **INV-APPSTATE-UNDO** — undo of background/name survives the next scene update, on both replicas. **GREEN (T028).**
- **Re-enabled multiplayer-undo block (34)** + restored collab.test.tsx cases. **Note: this block gates FR-009/010/011, not the wire** — that is why it must come after them.

## Migration strategy

Mirrors the #10 redesign discipline: **suite-first** (author every invariant red against today's code), **single-owner** (one author holds the lineage seam end-to-end — NO parallel-agent edge edits; that is the diagnosed defect source), **edge-by-edge** (each FR keeps the whole suite + typecheck + lint green before the next). Land on the PR #2 branch (`split/native-yjs-core`), superseding the throwaway-detour code (keep + extend its tests).

Order (**files boundary before wire**; write path before both): re-enable the disabled multiplayer block + write INV-CONVERGE / INV-WRITE-INTENT (RED) → **FR-009 write-path intent keys + FR-011 version guard** (the deepest fix; unblocks deleting 32 bandaids) → **FR-010 history lockstep** (together these three flip the re-enabled 34-test block green) → FR-001/002 wire → FR-004 cold-load → FR-003 persist → **FR-012 origin policy + FR-013 binaries off the wire** → FR-005 reveal → FR-006 GC → FR-007 save-skip → FR-014 robustness → FR-015 appState undo → full re-review (SC-003).

Rationale for the reorder: the wire fix was previously first as "the biggest correctness win", but INV-CONVERGE cannot go green while every local write clobbers whole elements — and the 34 re-enabled tests gate the write path, not the wire. Fixing the write path first also _removes_ code (32 bandaids), shrinking the surface every later phase has to keep green.

## Risks

- **R1 — `applyUpdateV2` fold must be over genuinely shared lineage.** If any path still mints fresh lineage, the fold silently whole-element-LWWs again. Mitigation: INV-COLD-LOAD-LINEAGE + INV-PERSIST-MERGE assert per-property survival across _independently adopted_ replicas, not just same-doc.
- **R2 — In-place GC racing a concurrent re-reference** (un-delete / re-add of an asset reference inside the timeout window). Mitigation: timeout-gated (only well-aged orphans); GC is a normal CRDT deletion so a concurrent re-add converges; INV-BOUNDED includes a concurrent-re-reference case.
- **R3 — Scene doc-adoption on cold-load** must not double-construct or leak the prior doc. Mitigation: adopt via the existing `options.doc` / `applyRemoteUpdate` path (Scene.ts:431/1037), verified by INV-COLD-LOAD-LINEAGE + the existing destroy()-ordering tests.
- **R5 — removing the 32 bandaids could mask an incomplete FR-009.** If any call site relied on the re-read for something other than the whole-object flush, deleting it silently changes behaviour. Mitigation: remove them one file at a time with the full suite green between, and treat any test that only passes WITH a bandaid as evidence FR-009 is incomplete — not as a reason to keep the bandaid.
- **R6 — intent keys must cover side-effecting helpers.** `redrawTextBoundingBox` / `updateBoundElements` / `bindOrUnbind` mutate through their own `mutateElement` calls; each must declare its own intent set or FR-009 leaks. Mitigation: INV-WRITE-INTENT exercises a container+bound-text edit, not just a simple property.
- **R4 — `dirty` flag correctness** (must set on LOCAL edits only, clear only on confirmed store write). Mitigation: INV-SAVE-SKIP covers both the redundant-save and false-skip directions.
